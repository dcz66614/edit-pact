## 每个问题的修复方法

- **P1-01 FR03（实现，非删减）**：新增纯字符串生成模块
  `src/core/instruction.ts`（`buildInstructionText`）：只含用户当前看到的
  内容——修改目标原文（未填时写“未填写”）、每段受保护段落的段号与逐字
  原文（按原稿顺序）、段数；无保护时明写“本轮没有受保护段落”；一句使用
  提示与一句不发送声明；不读任何内部状态（无 analysisId、revision、哈希、
  决定），不调网络或剪贴板接口，不发送任何内容；保护范围找不到对应段落
  时回退为按坐标切片原文，不编造段号。hook 从原稿草稿 + 目标 + 草稿中
  显示为已选的保护范围（id/起止三者一致，与 PreparePanel 选中判定同一
  口径）实时计算 `instructionText`，加 `instructionCopyState` 与
  `copyInstruction()`（经既有 `copyToClipboard`，失败置 failed）；
  `updateSession` 与 `clear()` 重置说明复制状态。PreparePanel 在目标
  输入下方渲染“改稿说明（可选）”区：只读 textarea + “复制改稿说明”按钮
  + 已复制/复制失败提示。单元 + 集成 + E2E 三层覆盖“说明内容与可见状态
  一致、无发送行为”（单元测试含模块源码无发送调用断言）。
- **P1-02 verify 脚本**：`scripts/verify.mjs`（仿 gate.mjs 写法），9 条子
  命令按 §10 顺序串行（typecheck、fixtures:check、test、test:invariants、
  build、test:e2e、test:privacy、benchmark、evaluation:check），任一非零
  立即停止并以非零退出；不调用自己、不调用 release:pack/release:verify。
  package.json 加 `"verify": "node scripts/verify.mjs"`。`npm run verify`
  已跑通（exit 0）。
- **P1-03 Worker 构造失败**：`DiffWorkerClient.analyze()` 内先以 CANCELLED
  结束旧待处理 job、终止旧 Worker，再 try/catch 包 `createWorker()`，
  构造失败返回 `Promise.resolve({ ok: false, errorCode: 'UNSUPPORTED_ENV',
  revision, jobId })`（恒返回 Promise，永不同步抛错）；`worker.postMessage`
  也包 try/catch，发送失败按 TOO_COMPLEX 兑现。hook 的 `beginCompareFlow`
  把 `client.analyze(request)` 包 try/catch 并接 `.catch`，任何同步抛错
  或 Promise 拒绝都进 error 阶段（UNSUPPORTED_ENV 文案）。单元（构造失败
  不抛错 + 旧 job 先 CANCELLED）与集成（error 面出现，不卡 comparing，
  有“重新比较”入口）覆盖。
- **P2-04 F07 测试**：两处 F07 数据与断言改写为真实 2-Hunk 模型
  （h1 [11,18) blocked、h2 [20,21) pending；compose 侧 decisions
  `{ h2: 'accepted' }`，期望成稿等于修复后的 expected.txt；保护映射
  prot-1 [9,16) → [9,16)），并注明旧版手写单 Hunk [9,24) 与修复后金
  标准矛盾。真实 Hunk 经临时探针跑真实 analyze 核对（探针已删）。
- **P2-05 返回审阅（保留决定）**：hook 加 `backToReview()`（只清
  `returningToPrepare` UI 状态，不碰 session，决定全部保留）；EditPactApp
  在 `returningToPrepare && session.analysis !== null` 时显示提示文案
  （改为“调整保护或原稿将清空旧的审阅决定；不改保护可直接返回审阅，
  决定全部保留。”）与“返回审阅（保留决定）”按钮；保护或原稿一旦改动，
  reducer 已清空 analysis，入口随之消失。集成 + E2E 覆盖（已采用 1 项
  往返后仍为已采用 1 项）。
- **P2-06 IME 守卫**：`commitOriginalDraft()` 在草稿确实与现原稿不同、
  即将真正提交时检查 `isComposingRef`，组合中返回 false 并设错误
  “输入法组合输入尚未结束，请先完成输入再继续。”；草稿无变化时直接
  放行（不影响不冻结任何内容的操作）。`beginCompareFlow` 已在调用前
  检查组合状态，故无双重报错。集成 + E2E 覆盖（组合中点复选框不勾选、
