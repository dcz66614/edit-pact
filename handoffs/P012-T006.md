RESULTS:
  - setDecision（冻结签名）：陈旧 analysisId（含 revision 不一致）→
    STALE_ANALYSIS；未知 Hunk → UNKNOWN_HUNK；接受 blocked（decision
    为 blocked，或 conflicts 非空——两者都查，防篡改绕过）→
    PROTECTED_CHANGE；失败不改变原 session；相同决定重复提交为幂等成功
    （同一引用，不增加 decisionRevision）；实际改变时新 session、
    decisionRevision + 1、不可变更新。
  - keepRemaining(session, analysisId)：陈旧 analysisId → STALE_ANALYSIS；
    只把 pending 改为 rejected，accepted 与 blocked 不动；有改变时
    decisionRevision + 1，无 pending 时幂等成功不增加。不提供“全部接受”。
  - changeOriginal / changeCandidate / changeProtections：revision 必须为
    大于当前值的大整数，否则抛 TypeError；用 text.ts canonicalize 规范化
    输入；三者均回 phase prepare、analysis 清空；原稿变化同时清除改稿与
    保护，改稿变化保留原稿与保护，保护变化保留两稿并存入保护副本；
    decisionRevision 不重置（只计数决定改变）。A→B→C→B 改回旧值仍是新
    批准轮次，旧 analysisId 恒为 STALE。
  - applyAnalysisResult(session, result, expectedJobId, { isComposing })：
    composition 期间、phase 不是 comparing、revision/jobId 任一不符均丢弃
    （applied:false、原引用）；双双匹配时安装结果的副本（analysis、
    protections、每个 Hunk 均复制，与调用方对象无共享引用），phase 为
    review；匹配的错误结果消费为 error 阶段、analysis 保持 null。
  - beginCompare：composition 期间返回原 session；否则进入 comparing 并
    清空旧分析（已接受的设计偏差，见 KNOWN_LIMITATIONS）。
  - cancelCompare：仅 phase 为 comparing 时回到 prepare 并清空分析；其余
    phase 返回原 session（同一引用），不销毁已完成分析。
  - clearSession（冻结签名）：返回全新空 session（原文 ''、改稿 ''、
    revision 0、decisionRevision 0、phase prepare、protections []、
    analysis null）；清空后旧 jobId 不可复用。
