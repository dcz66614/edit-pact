## 1 目的

比较“保护契约”（先标记必须原文保留的段落，再逐项审阅改动、只由原文 + 已批准改动合成最终稿）
与参与者真实现用方法（例如 Word 比较、人工重读、“其他不变”口头要求），在收益（不想要的改动
不进入最终稿）和负担（总时间、保护设置时间）上的差异。

本实验只回答“在合成任务上，保护契约是否比参与者现有方法更少漏掉不想要的改动、代价是否可接受”，
不回答市场推广意义上的普遍效果。

## 2 招募

- 目标招募 **8 人**，形成探索结果的最低人数为 **6 人**。
- 招募对象：日常工作中会用 AI 润色中文短文（通知、报销说明、排期、报价等）的成年人。
- 排除：参与过本原型开发或审查的人员；已看过本协议附录金标准答案的人员。
- 招募与联系：由用户（Sam）或 Muse 在已有授权渠道执行。**本轮（2026-11-05）没有发送任何邀请**
  （见 §9）。
- 参与者以匿名编号 P01–P08 记录，不记录姓名、联系方式或工作单位。实验全程不收集真实工作文本；
  受测内容全部为附录 A 的合成文本。

## 3 任务（冻结）

每人完成 **4 个配对任务**（T1–T4），每个任务用“对照方法”和“保护契约方法”各做一次，
共 8 次操作。任务内容不同，但错误类型、文本长度、可改范围相当；每份任务含 **1 个事先定义
的未经授权改动**（见附录 A）。同一参与者不重复处理相同正文：同一任务的两次操作使用同一对
原文/改稿（这是配对比较的定义），不同任务的正文互不相同。

- 对照方法：参与者真实现用方法，允许使用 Word 比较，不强制设一个弱基线。另用标准差异查看器
  补充测试一次，判断保护契约相对“只看差异”是否额外有价值（该次只记录是否漏采，不计入主要指标）。
- 保护契约方法：使用 T009 原型：粘贴原文 → 标记保护段 → 粘贴冻结改稿 → 比较 → 逐项审阅 →
  合成 → 导出最终稿。
- 改稿采用冻结的预置样本（附录 A），不现场调用模型，避免模型波动混淆界面效果。
- 独立评估者按附录 A 的金标准最终稿检查参与者提交的最终文本；参与者全程不能看到预埋的
  未经授权改动清单和金标准答案。

### 3.1 顺序平衡

每位参与者的 8 次操作按 AB/BA 平衡：

- 顺序 AB：T1–T4 先用对照方法，再用保护契约方法。
- 顺序 BA：T1–T4 先用保护契约方法，再用对照方法。

P01–P04 用 AB，P05–P08 用 BA；若只招到 6 人，前 3 人 AB、后 3 人 BA。
顺序以 `observations.csv` 的 `order` 列记录为准。

### 3.2 计时定义

- 总时间：从打开原文到得到可交付的最终文本为止，包含粘贴、保护设置、回外部页面和审阅操作，
  以秒计。两种方法用同一口径。
- 保护设置时间：仅保护契约方法，从开始标记保护段到完成标记为止，以秒计；对照方法该列为空。

## 4 指标（冻结定义）

### 4.1 主要指标（每任务、每方法记录）

| 字段 | 定义 |
| --- | --- |
| `unwanted_adoptions` | 该任务预定义的 1 个未经授权改动进入最终稿的数量（0 或 1） |
| `correct_compose` | 最终文本与附录 A 金标准最终稿逐字相同为 1，否则为 0 |
| `total_time_seconds` | 总时间（秒，> 0） |
| `setup_time_seconds` | 保护设置时间（秒，≥ 0；仅保护契约方法，对照方法为空） |
| `completed` | 完成并交付最终文本为 1，中途放弃为 0 |

### 4.2 次要指标（每参与者、实验结束时记录一次，8 行记录同一值）

| 字段 | 定义 |
| --- | --- |
| `willing_reuse` | 是否愿意在下次同类任务中继续使用保护契约方法（yes / no） |
| `states_limit` | 能否说出“文字保护不等于事实核查”（yes / no） |

### 4.3 派生指标（由 `scripts/evaluate.mjs` 按冻结规则计算，不手工填）

- 每人每方法的未经授权采纳数（4 个任务之和，0–4）。
- 两种方法的未经授权采纳总数（全部参与者之和）。
- 正确合稿率：`correct_compose = 1` 的任务占比（按方法分别计算）。
- 总时间中位数（按方法分别计算，仅计 `completed = 1` 的任务）。
- 保护设置时间中位数（仅保护契约方法，仅计 `completed = 1` 的任务）。
- 未完成比例（按方法分别计算）。
- 愿意再用比例（`willing_reuse = yes` 的参与者占比）。

中位数：升序后取第 `ceil(n/2)` 个值（n 为样本数）。

## 5 探索性继续门槛（冻结）

以下 5 条须**全部**成立，才可继续扩展；任一不成立即记为 `PRODUCT_VALUE_FAIL`，暂停扩展和效果宣传：

1. 至少 6/8 名参与者的保护契约方法未经授权采纳数**不高于**其本人的对照方法采纳数。
2. 保护契约方法的未经授权采纳总数**低于**对照方法总数。
3. 保护契约方法的总时间中位数**不增加**（≤ 对照方法中位数）。
4. 保护设置时间中位数 **≤ 45 秒**。
5. 至少 5/8 名参与者愿意在同类任务中再用保护契约方法。

若只招到 6 人：第 1 条门槛为 5/6，第 5 条门槛为 4/6，其余不变；报告时原样写出分母，
不得把 6 人结果写成 8 人口径。

若招到 7 人：第 1 条门槛为 6/7，第 5 条门槛为 5/7（按 8 人比例向上取整），其余不变；
报告时原样写出分母。

## 7 隐私与数据处理

- 只记录匿名编号、顺序、任务编号、方法、指标数值与 yes/no 回答；不记录姓名、联系方式、
  工作单位、真实工作文本。
- 受测文本全部合成（附录 A），不含真实机密。参与者自带的真实文本不进入实验记录。
- 观察数据只存本地 `evaluation/observations.csv`，不上传、不外发。参与者可随时退出，
  退出后其已记录行予以删除（删除动作记入报告附注）。
- 知情同意见 `evaluation/CONSENT.md`；未签署同意书的人员不进入实验。

## 8 记录格式

`observations.csv` 列头固定为：

```text
participant_id,order,task_id,method,unwanted_adoptions,correct_compose,total_time_seconds,setup_time_seconds,completed,willing_reuse,states_limit
```

取值规则：`participant_id` 为 P01–P08；`order` 为 AB 或 BA；`task_id` 为 T1–T4；
`method` 为 baseline 或 contract；`unwanted_adoptions` 为 0 或 1；
`correct_compose` 为 0 或 1；`total_time_seconds` > 0；
`setup_time_seconds` ≥ 0（contract 方法必填，baseline 方法为空）；
`completed` 为 0 或 1；`willing_reuse`、`states_limit` 为 yes 或 no，
同一参与者的 8 行取同一值。

每位参与者应有 8 行（4 任务 × 2 方法），不得缺行、不得重复行。

## 附录 A 冻结任务与金标准（合成文本，无私人内容）

保护区间为原稿规范化后的 UTF-16 单元坐标 `[start, end)`，与原型 `splitParagraphs` 的
段落切分一致。每个任务恰含 1 个预定义的未经授权改动；其余改动均为合法润色，
金标准最终稿 = 接受全部合法改动、拒绝未经授权改动后的文本。

### 任务 T1：会议通知

原文（3 段）：

```text
请在周五前回复确认。
人数上限为30人。
感谢配合。
```

改稿（冻结样本）：

```text
请在周五前回复确认。
人数上限为50人。
感谢您的配合。
```

保护：第 2 段“人数上限为30人。”，区间 `[11, 20)`。

预定义的未经授权改动（1 个）：人数上限 30 人 → 50 人。

合法改动：“感谢配合。”→“感谢您的配合。”

金标准最终稿：

```text
请在周五前回复确认。
人数上限为30人。
感谢您的配合。
```

### 任务 T2：报销提交

预定义的未经授权改动（1 个）：提交日期 11 月 20 日 → 11 月 25 日。

合法改动：“逾期不再受理。”→“逾期将不再受理。”

```text
请于11月20日前提交报销单。
本次金额为2400元。
逾期将不再受理。
```

### 任务 T3：项目排期


## 附录 B 实验流程单（执行时逐项打勾）

1. 确认参与者已读并签署 `CONSENT.md`，分配匿名编号。
2. 记录参与者真实现用方法（基线描述，如 Word 比较 / 人工重读 / 口头要求）。
3. 按分配的顺序（AB 或 BA）执行 8 次操作；每次计时从打开原文起，到交付最终文本止。
4. 每次操作后立即记录该行观察，不得事后补记或修改已记录的时间。
5. 实验结束时询问并记录 `willing_reuse` 与 `states_limit`。
6. 独立评估者按附录 A 金标准核对每份最终文本，填入 `unwanted_adoptions` 与
   `correct_compose`（评估者不得向参与者透露预埋改动清单）。
7. 运行评估与检查命令，核对状态与结论后写报告。
